MysteryStay — Intelligent Mystery Hotel Booking Platform

“Discover Hidden Stays. Unlock Better Deals.”

A high-performance modular monolith platform engineered to solve the online travel agency (OTA) rate-parity dilemma. MysteryStay enables premium hotels to monetize unsold room inventory at steep discounts (20%–70%) through an identity-masking pipeline that keeps hotel brands confidential until booking confirmation, protecting brand pricing power while delivering travelers unmatched luxury rates.

THE ARCHITECTURAL PROBLEM

OTA Rate Parity vs. Unsold Capacity

Hotels operate under strict rate parity agreements with global OTAs (e.g., Booking.com, Expedia). Offering public discounts directly breaches contracts. Unsold rooms, however, spoil at midnight with 100% margin loss.

ENGINEERED SOLUTION

Identity Masking Pipeline: Deals are indexed and searched solely by luxury amenity clues, micro-neighborhoods, and verified star ratings. Hotel brand names and exact GPS coordinates are cryptographically guarded until an HMAC-verified Razorpay payment hook executes.

CONCURRENCY & TRANSACTION SAFETY

Pessimistic Row Locking (SELECT ... FOR UPDATE)

Flash sales on limited luxury inventory trigger intense concurrent booking spikes. Standard optimistic locking causes high abort rates and poor traveler UX.

DATABASE LEVEL SERIALIZATION

Executed via @Lock(LockModeType.PESSIMISTIC_WRITE) on daily room inventory ledgers. Rigorously verified with 10 concurrent competing threads for 1 available room: exactly 1 acquires the lock, 9 receive structured 409 Conflict. Zero double-bookings.

STATE RECOVERY & REVENUE ENGINE

15-Minute Expiration Hold Sweeper

When a booking is initiated, inventory is locked in a PENDING_PAYMENT state. If a user abandons the checkout funnel, locked rooms would remain unavailable.

AUTOMATED INVENTORY RESTORATION

A background worker running @Scheduled(fixedDelay = 60000) sweeps stale pending transactions exceeding 15 minutes, marks the booking EXPIRED, and atomically restores room capacity to the live availability ledger.

MODULAR MONOLITH BOUNDED CONTEXTS

Zero Premature Microservice Overhead

Designed as a single deployable unit with strict domain boundary isolation. Modules communicate solely through public service contracts, ensuring atomic local database transactions and zero network partition failures.

Real-Time Collaborative Kanban Board (Trello Clone)

Full-stack collaborative task management platform engineered with bidirectional real-time synchronization across distributed clients.

ENGINEERING CHALLENGE

Traditional REST polling creates massive HTTP overhead and stale board views during multi-user collaboration. Furthermore, updating task order positions in a database column normally requires shifting all subsequent rows ($O(N)$ write operations), creating severe database lock contention when multiple users drag and drop cards simultaneously.

IMPLEMENTATION & DESIGN DECISION

Implemented WebSocket communication using STOMP protocol over Spring Boot, broadcasting state changes instantly to subscribed room channels without HTTP polling. Solved the reordering bottleneck by engineering a floating-point position indexing schema: moving a card between position 2.0 and 3.0 computes a simple midpoint assignment of 2.5, transforming an $O(N)$ row cascade into an $O(1)$ single-row update.

02.2 / CONCURRENT FINANCIAL TRANSACTIONS
Jul 2026

Secure E-Bidding & Auction REST API

High-throughput, role-based backend engine for real-time auctioning with concurrent bidding integrity and cryptographic token authentication.

ENGINEERING CHALLENGE

Auction systems face extreme concurrency in the final minutes before auction close. When hundreds of users place bids at the exact same millisecond, standard database transactions can suffer from the lost update anomaly (where two bids overwrite each other, recording a lower price as winner), while excessive table locks degrade latency.

IMPLEMENTATION & DESIGN DECISION

Engineered role-based access control (RBAC) via stateless JWT authentication with granular authorization. Implemented JPA Optimistic Locking (@Version) on auction entities: concurrent bid collisions trigger clean version mismatch retries without blocking read throughput. Architected an automated auction expiration scheduler that marks auctions resolved and executes winner validation with centralized global exception handling via @RestControllerAdvice.
